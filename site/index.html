COLLABORATIVE ASTROPHOTOGRAPHY

Many rigs.
One picture.

A project sets out one image to build: its targets, filters and depth. Contributors work on their own nights with their own gear. Each rig checks in and gets an assignment: the part of the picture that most needs data and suits that rig. Accepted data from everyone adds up to the shared goal.

WORKFLOW

Each rig works alone.
The picture adds up.

Nobody coordinates by hand. The server tracks how deep each part of the picture is and steers each rig to where it helps most. Contributors keep full control of their equipment and nights.

01 / JOIN

Join and pair

Join a project on its web page, then pair each rig for its own key. Register the rig once; it serves every project you join.

POST /pair ↗ 02 / IMAGE

Check in, get an assignment

Each check-in returns the panel that most needs data and fits the rig: where to point, the filter, the exposure and how many frames. Report what you have captured, even before you upload.

POST /me/checkins ↗ 03 / CONTRIBUTE

Send your data

Upload calibrated subs or your own stacked masters, as the project asks. The server checks them and credits accepted data to the shared goal.

POST /projects/{id}/submissions ↗

CHECK-INS

Your part
of the picture.

A long lens gets one panel of a large target; a wide lens may get the whole thing. As panels fill, later check-ins move each rig on. The server assigns; there is nothing to negotiate.

  • Panels sized to each rig's field
  • Filters, sampling and camera angle
  • Local safety and acquisition control

REQUIREMENTS

Protocol rules

Read the protocol →
◎

No target locks

Plans reserve nothing. Two rigs may image the same panel, and useful data from both counts.

⌁

Credit counted once

The server checks quality, then credits accepted data. Each sub counts once, whether it arrives alone or inside a master.

↗

Your rig, your rules

The server suggests; your software decides. Any scheduler, camera software or catalog works.
